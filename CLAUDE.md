# Poor Fantasy — instructions for Claude

A personal, nostalgic party-based fantasy RPG in the style of the late-1980s "Gold Box" games, built on the current D&D rules (SRD 5.2). Personal project; optimise for **fast playtest iteration**.

## Stack (decided — do not change without asking)
- **Phaser 4** (pinned exact version) for map, combat and dungeon rendering. WebGL renderer (`Phaser.AUTO`); Canvas renderer is deprecated in v4.
- **TypeScript** (strict), **Vite** (dev server + build), **Vitest** (tests).
- **HTML/CSS overlays** for menus, character sheets, shops, the message log. Do not build text-heavy UI in Phaser.
- Content as **JSON** in `src/content/`. Maps will be authored in **Tiled** (JSON export).

## Architecture rules (enforced by `tests/architecture.test.ts`)
1. `src/engine/` and `src/rules/` are pure TypeScript: **no Phaser, no DOM, no imports from `game/` or `ui/`**. All rules logic lives here and is unit-tested.
2. `src/game/` (Phaser scenes) only renders state and forwards Commands. No rules logic in scenes.
3. **All randomness goes through `Rng`** (`src/engine/rng.ts`). Never call `Math.random()` in game logic. `?seed=N` in the URL replays a run exactly.
4. **Input is Commands, not keys** (`src/engine/commands.ts`). Key codes appear only in `src/game/input/keyboard.ts`. Every action must be reachable by touch.
5. Game state (`src/engine/state.ts`) is plain JSON-serializable data. Bump `SAVE_VERSION` when its shape changes.
6. Mode changes must be allowed by `TRANSITIONS` in `src/engine/modes.ts`.

## The seven modes (each becomes a Phaser scene)
party (roster/creation) · explore (first-person dungeon + overhead wilderness) · encounter (fight/parley/flee/wait/advance) · combat (tactical grid) · postCombat (XP/loot) · camp (short/long rest, spells, save) · town (shop/temple/training/inn).

## Rules source
SRD 5.2 (2024 rules), CC-BY-4.0. Implement from the SRD, cite the section in code comments for non-obvious rules. Never copy code, text, maps, art or data from the original SSI games or from reverse-engineered sources (e.g. talonius/pool-of-radiance) — architecture reference only. Do not use the original game's name in the project.

## Phaser skills
Official Phaser 4 skills are in `.claude/skills/` (copied from the pinned `phaser` npm package). **Read `v3-to-v4-migration` before writing Phaser code** — avoid v3 idioms (pipelines, FX/masks → filters, tint changes).

## Workflow
- `npm run dev` — play at http://localhost:5173 (hot reload). `npm test` — rules tests. `npm run build` — typecheck + production build. `npm run sim` — balance simulator (bot win rate for the test encounter); rerun after changing monsters, encounters or combat rules.
- Before committing: `npm run build && npm test` must pass.
- Work items live in Jira project **DND** (tobyjamesmerritt.atlassian.net). Reference the key in commit messages, e.g. `DND-12: add opportunity attacks`.
- Keep changes small and playable. Prefer a rough playable feature over a polished unplayable one.

## Conventions
- New rule → pure function in `src/rules/` + tests with a scripted or seeded `Rng`.
- New content type → JSON file in `src/content/` + a TypeScript type; validate at load.
- Monsters: SRD 5.2 stat blocks only, in `src/content/monsters.json`; encounters reference them by id. Check difficulty against the SRD XP budget (`encounterBudget`).
- Art goes in `public/assets/<tiles|sprites|portraits|ui|audio>/`; see `docs/art-pipeline.md`.
- Maps are Tiled JSON in `public/assets/maps/`. Impassable tiles carry the tileset tile property `blocked: true`; locations live in the `locations` object layer (type town|cave|ruins, properties `locationId`, `description`; one `start` object). `src/content/world.ts` validates and converts them; `src/rules/world.ts` does travel. `tools/gen-world.mjs` generated the first world map — never rerun it once the map has been edited in Tiled.
- Navigation commands (`worldMap`, `enter`, `leaveLocation`, `fight`, `endFight`, `newFight`, `restart`) are handled in `main.ts`; scenes handle gameplay commands. `main.ts` also sets the canvas size and `body[data-mode]` layout per scene. Layout is the same on every game screen: game (stage) left, party panel (#left, area `side`) right, message log below; narrow screens stack panel · game · log.
- Encounters: one JSON per fight in `src/content/encounters/` (register it in `encounters.ts`). `?encounter=<id>` jumps straight into a fight.
- Characters: `GameState.roster` holds character sheets (class, species, background, base scores, background increases — SRD 5.2). Everything else is derived by `rules/character.ts` (`deriveStats`) from `src/content/{classes,species,backgrounds,gear}.json`; scenes use `membersOf(game.roster)` / `statsOf(...)` from `content/characters.ts`, never static data. `party.json` = quick-start pregens. Unplayable classes/traits/feats are kept as data (`playable: false`, `IMPLEMENTED` list) so they can be switched on later. Party screen = HTML (`ui/partyScreen.ts`, mode `party`); new games allow full edits, during play only name/portrait. Character pool: `GameState.bench` holds any number of extra characters (with their condition); `rules/roster.ts` does add/bench/join/delete/ready-made (max 6 in the party). New game keeps the pool and restores everyone. Debug URLs skip creation and use the pregens.
- Locations (towns, dungeons): `src/content/locations.json` maps a world `locationId` to its map file + intro text. Each location is a 16×16 Tiled map `public/assets/maps/<id>.json` (layers `ground`, `structures`, object layer `spots`: entrance (facing), exit, fight (encounter), building (building; its square is the door — drawn as a door in the 3D view, Tiled bool `locked` + optional `unlockFlag` keep it shut: `doorLocked`), text). Solid squares = tileset property `blocked`; their look in the 3D view = tileset property `material` (stone, rock, tree, wood). Loaded/validated by `src/content/locationMap.ts`; movement + first-person view geometry in `src/rules/location.ts`; `LocationScene` renders the 3D view (left) and overhead map (right). Cleared fights: `flags["cleared:<locationId>:<spotId>"]`. Fog of war on the overhead map: `visibleSquares` (line of sight; `SIGHT` towns 5 / dungeons 1, strict corners in dungeons; `sight` in locations.json overrides), remembered in `GameState.explored` (hex bitmask per location, save v11 — never fogs again); click-walking only to/through seen squares. World map fog: `worldSight` (3 squares by day, 2 dusk/dawn, 1 at night, no line of sight), key `world` in `GameState.explored`. Fog is drawn soft by `spriteCss.ts SoftFog` (small canvas texture, blurred in code, smooth upscale; unexplored stays solid). `?location=<id>` jumps straight in. `tools/gen-locations.mjs` generated the starter maps; it refuses to overwrite (use `--force <id>` only for maps nobody has edited in Tiled).
- Game clock: `GameState.time` in minutes; costs per step in `src/rules/time.ts`.
- Saving: `engine/save.ts` (pure) = save envelope (`makeSave`/`parseSave`, `MIGRATIONS` table — add a step whenever `SAVE_VERSION` changes, so old saves keep loading) + character library (`remember`/`forget`; deleted ids are tombstoned and never return). `ui/saveStore.ts` = localStorage (slots auto, 1–3; key `poor-fantasy.characters` for the library). `main.ts` autosaves on scene changes and when the page is hidden/closed, continues from the autosave on startup, and never saves in combat, during party creation, or from debug URLs. Save/load/export/import dialog: `ui/saveDialog.ts`; styled yes/no: `ui/confirmDialog.ts` (use it instead of `confirm()`).
- Persistent party: `GameState.party` (hp, hitDice, dead, wakesAt) + `coins` (copper). Fixed stats are derived from the roster (see Characters). `main.ts` copies fight results back with `rules/party.ts` (`afterCombat`, `afterDefeat`); combat starts from the stored HP. Exploration randomness (rests, ambushes) uses `exploreRng` in `main.ts`, separate from the replayable combat seed.
- Resting: `rules/rest.ts` (SRD 5.2 Short/Long Rest, Modest inn 5 sp/person, house-rule ambush risk per site). Where camping is allowed: `worldCampSite` (rules/world.ts, terrain from `src/content/terrain.json`), `locationCampCheck` (dungeons), inns via the building panel. `CampScene` draws a background per site kind; ambushes use encounters `ambush-wilds` / `ambush-dark`.
- Economy: items in `src/content/gear.json` (SRD 5.2 prices in copper; refs `weapon:<id>`, `armor:<id>`, `shield`, `consumable:<id>`), party pack `GameState.inventory`, equipped gear on `CharacterSheet.gear` (absent = class kit). `rules/items.ts` buy/sell (half price)/equip/unequip with SRD armor & weapon training; `rules/rewards.ts` XP split among surviving fighters + fixed treasure per fight spot (`src/content/treasure.json`, beasts carry none); `rules/services.ts` temple heal/raise (house prices in `services.json`). Shop = HTML (`ui/shopScreen.ts`, mode `shop`). Potion of Healing in combat = Bonus Action (`usePotion`, `CombatState.bonusUsed/potions`). XP lives on the character sheet (`sheet.xp`).
- Levelling: `rules/levelling.ts` (SRD 5.2: Hit Die roll or fixed value + Con, +1 Hit Die, Proficiency Bonus by level, ASI at 4; levels up to `MAX_LEVEL` = 5). Sheets record `hpGains` (die result per level) and `asi`; `deriveStats` recomputes everything from them. Class feature names per level in `classes.json` `featuresByLevel` — listed in the level-up panel, only those in `IMPLEMENTED` work. Level up from the party screen (Level up! button), anywhere outside combat.
- Combat action economy (SRD 5.2, `rules/combat.ts`): movement splits freely around the action; one action (Attack = move into an enemy, Dash/Dodge/Disengage via `takeAction` / command `combatAction`, Help, a spell), one Bonus Action, one Reaction per round (`Unit.reactionUsed`, regained at the start of its own turn). Opportunity attacks (`provoke` in `step`, also when fleeing off the edge): leaving an enemy's reach draws one melee attack per enemy that still has its Reaction, unless Disengaged; a mover dropped by one stops and its turn ends. Dodge = effect `dodging` (disadvantage against it, advantage on Dex saves). The combat card shows Action · Bonus · Reaction.
- Class features in combat (DND-52, `rules/features.ts`): names from classes.json (`featureNames`) → `combatFeatures` (Extra Attack = `Unit.attacks`, the Attack action lasts until `CombatState.attacksMade` reaches it; Sneak Attack with a Finesse weapon, Cunning Action = `takeAction(..., bonus)`, Uncanny Dodge, Champion `critOn` 19, Colossus Slayer; once-per-turn riders tracked in `Unit.onceTurn`). Per-rest uses (`second-wind`, `action-surge`, `lay-on-hands` pool) live on `Unit.uses`, spent ones in `PartyMemberState.featureUses` (`usesSpent` after a fight, `restFeatures` on rests). `featureOptions`/`useFeature` + command `useFeature` drive the card buttons. Fighting Style is always Defense (+1 AC in armour, in `deriveStats`); Life Domain's Disciple of Life = `CasterInfo.discipleOfLife`.
- Enemy AI v2 (DND-16, `runEnemyTurn` in combat.ts): `pickTarget` (fight whoever is adjacent; else among those reachable this turn: can be finished off › concentrating caster › lowest AC › most hurt; Pack Tactics favours targets an ally already touches; nobody reachable → nearest); `bestStepToward` is a breadth-first path around bodies and other monsters; morale (house rule) = monsters.json `morale` (HP fraction; beasts 0.25) or over half their side down → DC 10 Wis save each turn, failure = `routed`: Dash to the nearest edge and leave (`fled`). Routed monsters count as beaten (XP) and don't block Victory. No ranged monsters yet, so no ranged behaviour.
- Items in combat (DND-24): potions (Bonus Action) and Spell Scrolls (spell list) as before; weapons: `membersForFight(roster, inventory)` gives each member `weapons` (the one in hand + every weapon in the pack, with that weapon's numbers); `swapWeapon` (command `swapWeapon`) = the free object interaction, once a turn (`CombatState.objectUsed`); pack spares are counted in `CombatState.packWeapons` so one dagger can't be in two hands. Swaps last for the fight only — the pack and sheets don't change.
- Debug console (DND-20): About dialog → typed commands dispatched as `{type:'debug', text}`, parsed in `main.ts` (help, gold, xp, heal, fight <encounter>, time, seed <n> = next fight's dice, fog); `kill` is the only one allowed mid-fight and is handled by `CombatScene`. Backtick (command `openDebug`) opens it with the input focused. Hotkeys (DND-82): `keyboard.ts` `KEY_MAP` (everywhere) + `SCREEN_KEYS` (only on the listed `body[data-mode]` screens: N encamp, L leave, P party, K pack, J journal); buttons underline their letter (`hotkeyLabel` in hud.ts, `<u>` in index.html). Unit inspect (DND-83): tap a turn-order row → `TurnEntry.detail` lines from `CombatScene.inspectLines` (HP, AC, speed, attack, size/type, dying state, conditions, concentration, slots). Combat extras: floating HP numbers (`CombatScene.floatNumber`), turn order bar (`hud.setTurnOrder`), opportunity-attack warning on click-to-walk (`pathProvokes` — second click goes anyway), hotkeys H/O/G = Dash/Dodge/Disengage.
- Player preferences (grid, auto-end turn, text size, difficulty = retreat rule hard|normal|casual, read at fight start) live in `src/ui/prefs.ts` (localStorage).
- Magic: `rules/spells.ts` (SRD 5.2 Spellcasting: slots, cantrips, prepared spells, Wizard spellbook + Arcane Recovery, spell attack/DC, one slot per turn, Concentration, cantrip scaling, upcasting) + `src/content/spells.json` (implemented spells only; add more as data with an `effect.kind` the engine knows). Class tables in `classes.json` `spellcasting`. Sheet: `cantrips`/`spellbook`/`prepared` (absent = recommended picks); party state: `spells.used`, `tempHp`, Mage Armor end time. Effects/Concentration/temp HP hooks live in `rules/combat.ts` (`hurt`, `healUnit`, `attackMode`, `addEffect`). Combat: card spell list → `aimSpell` → grid picks (CombatScene). Outside fights: `ui/spellsDialog.ts` (camp + party screen; per caster: slots "Level n: x of y", prepared as chips, one row per castable spell → Cast… panel with slot level + targets most-hurt-first; scrolls listed separately; `openSpells` with `characterId` shows one caster); prepared spells change only at camp after a Long Rest (`flags['spells:prepare']`). Monsters need `saves` in monsters.json (and `type`/`size`: Divine Smite vs fiends/undead, Large+ Advantage vs Ensnaring Strike). Paladin/Ranger (half-casters, no cantrips): class `always` (spells kept prepared from a level, not counted) and `free` (casts per Long Rest without a slot: Paladin's Smite, Favored Enemy → `CasterInfo.free`, spent ones in `SpellState.free`; a free cast is slot 0 in `castOptions().levels`). Smites (`effect.kind: smite`) are readied (`CombatState.smite`) and fire — paying slot + Bonus Action — on the next weapon hit that turn (`fireSmite` in combat.ts; house approximation of SRD's cast-after-the-hit). Weapon-hit riders: `hitRiders` (Hunter's Mark `marked`, Divine Favor), Magic Weapon `magic-weapon` amount; start-of-turn effects (`searing`, `restrained`, `heroism`) in `startOfTurnEffects`; restrained enemies with nobody in reach spend their action to `breakFree`.
- Quests: `rules/quests.ts` (pure engine: conditions, actions, dialogs with skill checks, hooks, world sites, triggers) + `src/content/quests.json` (all quest content — no quest is hard-coded). Progress = flags (`quest:<id>` stage, `found:<site>`, custom). Hooks attach content to a building (`"<location>/<spot name>"`, buttons in its panel; `replaces` hides its services) or a world site (`"site:<id>"`, fires on arrival or when bumping a blocking site). World sites are Tiled objects of type `site` (siteId, description, hidden) in world.json's `locations` layer; icons/blocking in quests.json `sites`. Actions that need the screen (dialog, fight, enter) come back as Requests; `main.ts` runs them (conversation = `ui/talkDialog.ts`, journal = `ui/journalDialog.ts`: list of name + `summary`, click for stage text and a checklist from `tips` via `questSteps`). Quest fights carry `onWin`/`onLose`/`onFlee`, optional `difficulty` and monster `tweaks` (e.g. fumble). Places inside a town (the shrine) are locations with `parent` in locations.json. New games start inside Millbrook.
- Fight scaling: `rules/scaling.ts` — SRD 5.2 XP budget for (party size − 1) at the party's level, and never more monsters than party members (house rule); encounters with `scaling` (difficulty, fixed monsters, filler monsters min–max) are resolved by `resolveEncounter` at fight start. `npm run sim` runs every encounter at levels 1 and 3.
- Items: `weapon:<id>+1` (magic weapons, SRD value), `scroll:<spell>` (Spell Scrolls: castable by classes with the spell on their list, scroll's own DC/attack, in combat and from the spells dialog), `misc:<id>` (quest items, unsellable), `consumable:ale` (not on shop shelves). Random loot for quests: `random:weapon+1`, `random:scroll:<class>:<level>` (`rules/items.ts rollLoot`).
- Pack: `ui/packDialog.ts` (Game → Pack…, party screen, camp; not in combat) — purse, category tabs (only those with items), one card per item with an icon (`item-*` sprites in assets.json, Tiny Dungeon frames) and one button; Drink…/Equip… open name chips on the card (disabled chip = can't use it, reason in the tooltip); below, a compact who-wears-what list whose names open the character sheet; drinking potions/ale uses `rules/items.ts useItem` (command `useItem`), gear uses the shop's `equipItem`/`unequipItem` commands, scrolls open the spells dialog. New games start with 2 Potions of Healing (`STARTING_POTIONS` in main.ts, house rule).
- Random encounters: `rules/wandering.ts` + `src/content/wandering.json` — chance per world-map step (none on roads/bridges, a zone may set its own chance — 3% near settlements, 8% elsewhere; grace steps after one), zone by distance to the nearest town/site (hidden ones too): difficulty + monster share of the party size + which quests.json dialogs (`wander-*`: fight or Dexterity (Stealth) slip away). Encounters `wild-*`. The status bar names the zone.
- Wounded warning: `main.ts partyHurt/warnIfHurt` asks before quest fights and dungeon spot fights (anyone down/dead or under half HP); ambushes and random encounters can't be put off.
- Party dialog: `ui/partyDialog.ts` — every side panel lists the party the same way (`hud.ts rosterList`: portrait, name (class), HP bar) under a "Party ▸" header (command `openParty` → group view: level, HP, AC, XP, Level up!, Pack/Spells/Roster). Clicking a name (`openCharacter`) opens that character's sheet — one fixed size for every class (portrait, abilities, combat numbers, equipment, a compact spell summary + Spells… = `openSpells` for that caster); clicking an equipped item opens a gear pop-up of what in the pack fits that slot (`equipItem`/`unequipItem`). Level up! opens the roster screen on the level-up panel (`partyScreen` with `levelUp`).
- Party name: `GameState.partyName` (optional, save v10), set on the party screen; shown on the world-map roster, the pack and save labels. The pack is shared by the whole party; only equipped gear belongs to a character.
